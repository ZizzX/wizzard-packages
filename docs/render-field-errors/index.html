Render field errors

Validation messages are keyed by field, so each one can be drawn next to the input it is about rather than collected into a list at the top of the form.

Press Next with both fields empty.

  • React
  • Vue
  • Headless

One message per field, keyed by the field name. The keys are what make the placement possible.

The field and its message are one component, so the two cannot drift apart.

A test in the repository asserts these exact lines.

Reading the messages

Section titled “Reading the messages”

useErrors() returns the map for the current step, or for a step you name. It is a plain object keyed by field:

On Vue it is a ComputedRef of the same object, which the template unwraps for you.

Making it accessible

Section titled “Making it accessible”

Three attributes do the work, and the example above carries all three:

  • aria-invalid on the input, so the field announces itself as wrong.
  • aria-describedby pointing at the message’s id, so the message is read with the field rather than stranded somewhere after it.
  • role="alert" on the message, so it is announced when it appears.

A message that is only a red border says nothing to anyone who cannot see the border.
